# Task 09A — Reliable AOSC Enrollment and CPU/Vulkan Identity Consistency

## Verdict

**B — Partially Improved.** A bounded four-order enrollment search with independent held-out enrollment validation raised usable registrations from 36/48 (75.0%) for the matched Task 08 control to 47/48 (97.9%). This is a real enrollment improvement on the matched VCTK cohorts. It does not meet the end-to-end objective: unknown false acceptance increased from 43/144 (29.9%) on evaluated Task 08-control unknown queries to 84/188 (44.7%) after repair, and the eight-speaker selected profiles falsely accepted 59/60 unknown queries. The profile search therefore must not be called a successful production policy.

The original full Task 08 cohort remains 216/288 (75.0%) AOSC-ready and map-valid. Task 09A added enrollment evidence checks and order search, but the selected query results are a follow-up analysis of the Task 08 development, calibration, and already inspected final-holdout speakers. They do not establish a new speaker-independent final result.

### Concrete failure cases

* **Genuine stable collision — `development_n2_r03_e10_randomized`.** p228 had 1,217 ground-truth VAD speech frames and 1,067 native-active frames; p297 had 1,087 VAD frames and 927 active. The per-identity confusion matrix therefore has both labels concentrated on channel 0, rather than useful evidence on a competing channel. The result persisted across three versus seven utterances. The segmenter emitted ten channel-0 regions overlapping both labels. The cache performed five compressions; the first retained 136 positive p228 rows and 29 p297 rows from 30 p297 rows. Compression skewed the amount of retained evidence but did not create the shared channel.
* **Unstable/weak establishment — `development_n4_r01_e05_randomized`.** p228 had 682 VAD speech frames and 413 active frames. ## Mapping alternatives

The baseline remains the independent strict rule: per identity, select its unique dominant top-1 activity channel on VAD speech frames; require dominance at least 0.5 and mean candidate probability at least 0.5; reject any channel shared by two identities.

The research helper evaluates a full identity-by-channel activity matrix and a maximum-weight one-to-one assignment over eight native channels. It also requires independent per-identity evidence for the assigned channel: at least half of that person's active top-1 frames and mean assigned probability at least 0.5. A unique optimum alone never makes a profile valid.

| Failed profile class | Unique global optimum | Evidence-supported global assignment |
|---|---:|---:|
| Collision records (40) | 26 | 0 |
| Channel-establishment records (24) | 23 | 0 |

Nine collision profiles and two establishment-failure profiles had some noncandidate active top-1 evidence, but that was insufficient to support a full unique mapping. No failed Task 08 profile gained an evidence-supported valid mapping. The same guard added no candidate-suite profiles beyond strict mapping. The exhaustive assignment can produce a unique answer by placing an identity on an unused channel with negligible evidence; accepting that answer would convert model confusion into a false identity claim. Tests cover a genuinely distinct assignment, a shared-channel collision, tied/weak activity, a supported assignment, forced unsupported assignment rejection, and mapping validation after AOSC import.

Temporal diagnostics show channel changes are common, but do not justify dropping minority-channel evidence as a general rule: 61/72 failed profiles had within-utterance top-1 transitions and 45/72 changed dominant channel between enrollment clips. The candidate search instead checks held-out enrollment utterances independently and rejects a profile when any validation utterance does not support the assigned channel. No frame-smoothing threshold or “ignore short run” rule was added; the same stream often contains true multi-speaker channel confusion, and the development/calibration sample does not support a production threshold for suppressing it.

## Stage 2 protocol and bounded repair experiment

The deterministic v1 suite contains 216 matched construction candidates for 48 cohorts (16 each with 2, 4, or 8 enrolled people, at 15, 30, 45, or 60 seconds/person). Each cohort uses the same construction utterances across grouped, reversed group order, round-robin, and seeded-shuffle order. The extra v2 manifest adds 27 inter-speaker pause variants. Additional groups compare per-clip pauses and six utterance-selection variants. Total attempts: 243. All construction and validation audio comes from each enrolled speaker's enrollment partition.

For a candidate to pass independent enrollment verification, each excluded construction utterance is checked against its assigned channel: a unique active top-1 dominant channel, at least 0.5 share, and assigned mean probability at least 0.5. This reuses the existing strict criteria as an enrollment-only validation rule. A candidate is eligible only with AOSC ready and strict or evidence-guarded global mapping plus validation pass. Strict mapping is preferred when both qualify. The fixed search budget is four candidates per cohort; every planned attempt must return. Selection among eligible candidates maximizes the equal-identity mean assigned-channel top-1/top-2 margin on the held-out enrollment utterances, with trial ID as tie-break. Evaluation queries and unknown holdout speakers are not read by selection. If no candidate passes, the group abstains. This was a research procedure, not a production threshold policy.

All 243 candidate profiles were AOSC ready. 183 passed strict mapping and independent verification; 3 had valid strict maps but failed independent verification; 57 had invalid strict mapping. The selected search yielded 47/48 verified profiles, compared with 36/48 for the matched grouped-order baseline. Eleven groups whose grouped candidate failed passed under a different order. Order success across all 48 matched groups was grouped 36/48, reversed 43/48, round-robin 35/48, seeded shuffle 37/48. Reversal helped these speakers, but round-robin was not better than the baseline; order sensitivity is cohort-specific.

| Enrolled people | Matched grouped baseline | Four-order selected profile |
|---:|---:|---:|
| 2 | 16/16 | 16/16 |
| 4 | 14/16 | 16/16 |
| 8 | 6/16 | 15/16 |

At the 15/30/45/60-second budgets, baseline versus selected counts were n2: 4/4 at every duration; n4: 3/4, 3/4, 4/4, 4/4 versus 4/4 at each; n8: 1/4, 1/4, 2/4, 2/4 versus 3/4, 4/4, 4/4, 4/4. Longer speech was associated with more valid n8 profiles in this small matched set, but the cache is bounded and duration did not produce proportionally more retained rows.

The grouped-order baseline by partition was development 17/24 and calibration 7/12; repair selected 23/24 and 12/12. The previously inspected final-holdout follow-up was 12/12 for both. The overall selected result was 47/48. Mean attempts per usable profile was four because the experiment exhausted all four planned orders before selection; there were no early exits that could silently reduce the denominator.

### Pauses, utterance selection, and turns

On matched speaker-boundary-only pause cases (same utterances, 9 profiles total), 0 ms yielded 6/9 usable profiles, 250 ms yielded 5/9, and 500 ms yielded 6/9. Altering every clip pause yielded 6/9 at 0 ms and 5/9 at 500 ms. No monotonic pause effect appears. The Task 08 default was 250 ms after every clip. The small utterance-selection comparison did not show a consistent winner (2/3 usable in either compared selection). These ablations are too small to tune a general pause or selection rule.

The matched order suite compares consecutive same-speaker blocks with round-robin short turns and selected permutations. It finds large per-cohort order effects, but not a general benefit from alternating turns. This model carries temporal state across input, and a change in preceding-speaker context can change channel assignment; the data do not isolate a universal optimal turn length.

## AOSC cache preservation and profile readiness

The observer records per-compression input and retained prediction rows with source-frame lineage. It makes no change to compression selection or codec state. Across 5,585 compression events, source rows for later enrollment positions were retained less often when they were present before compression. Mean retention ratios by cohort size and enrollment position were: n2 0.977 then 0.655; n4 0.985, 0.913, 0.803, 0.578; n8 0.985, 0.958, 0.950, 0.931, 0.909, 0.879, 0.741, 0.553. This is a descriptive, conditional-per-compression comparison; enrollment position is confounded with how many positive rows existed at that event. It indicates order/cache effects, not a compression defect.

All selected candidate records had a fixed 264-row cache; median AOSC profile size was 551,305 bytes. Mapped-channel argmax-row medians were 128 for n2, 48 for n4, and 25 for n8 (minimum n8 24), with no mapped channel having zero rows. Increasing duration did not scale cache capacity: n8 medians were 24, 25, 24, and 27 rows per identity at 15, 30, 45, and 60 seconds/person. In the 216 order candidates, all eight predicted channels were occupied for every n8 cohort. Cache evidence quantity by itself did not predict UNKNOWN rejection: all 39 strictly mapped n8 candidates that passed enrollment validation had perfect known query classification, yet their mean unknown false-accept rate was 1.0 in the sampled n8 query set. The engine has no unused native channel available to reject unknowns once all eight channels map to registered people.

Readiness, map validity, and independent verification are reported separately. In Task 08, only readiness and map validity were available, so “verification not provided” is retained as a distinct baseline status.

## CPU/Vulkan parity

The detailed fixed-profile factorial results for PV-01, PV-02, and PV-03 are in [voiceid_task09a_backend_parity.json](../tests/results/voiceid_task09a_backend_parity.json). The runner completed 16 separate-process runs: two independent CPU constructions, two explicit Vulkan 0 constructions, and twelve exact-profile imports (each source profile imported into both evaluation backends). For each import, the source bytes and imported bytes had matching FNV-1a and CRC checks. The CPU and Vulkan profiles both reproduced byte-for-byte in their second construction; query traces also repeated byte-for-byte on each same backend. Thus, the measured difference is deterministic across backends rather than same-backend nondeterminism.

The original Task 08 sample had three decision changes among 33 queries, 1,050 changed top-1 frames among 15,713 compared frames, and maximum absolute probability error about 0.571. Identity maps were equal while profile CRCs differed in PV-01, PV-02, and PV-03. PV-01 (4 enrolled) changed from CPU UNKNOWN rejection to Vulkan acceptance of an identity; PV-02 and PV-03 (8 enrolled) changed from CPU no-decision to Vulkan UNKNOWN false acceptance. This independent-profile comparison mixed enrollment construction and evaluation effects, which the fixed imports separate below.

CPU and Vulkan strict identity maps matched in all three profiles. The CPU profile construction differed from the Vulkan profile in all three cases; all current Vulkan profile SHA-256 hashes exactly matched the saved Task 08 Vulkan profiles. For n4 PV-01, final positive rows by channel were equal (`[112,48,48,48,0,0,0,0]`) despite row source/embedding differences. For the shared n8 PV-02/PV-03 profile, CPU retained positive rows were `[48,24,37,29,46,24,24,24]`, versus Vulkan `[48,24,27,24,24,45,24,40]`. The eight assigned identities still mapped to the same channel numbers, but cache balance across channels changed.

| Construction state | Profile state difference, CPU vs Vulkan |
|---|---|
| PV-01 n4 acoustic cache | 131,072/135,168 values differ; max absolute error 150.132, MAE 4.327, RMSE 7.807. Prediction state: 2,009/2,112 values differ; max 0.0330, MAE 0.000356, RMSE 0.001865. |
| PV-02/PV-03 n8 acoustic cache | 133,631/135,168 values differ; max 133.314, MAE 5.697, RMSE 9.086. Prediction state: 2,061/2,112 values differ; max 0.9992, MAE 0.08887, RMSE 0.29196. |
| Learned silence state | Identical across backends for both profile sizes. |

The cache array differences above are elementwise serialized-state differences; where row lineage differs, they combine selected-row changes with numeric content changes and are not a direct per-frame inference error. In the source-lineage trace, compression inputs had identical ordered source rows for 11/116 events in n4 and 9/279 in n8. The first retained-row mismatch happened at zero-based compression event 7 for n4 and event 8 for n8, while that event's input source-row lineage still matched. Later input lineages diverged. Across all events, retained rows matched exactly for 10/116 n4 events and 8/279 n8 events; mean retained-row set Jaccard was 0.850 (minimum 0.620) and 0.692 (minimum 0.373), respectively. This indicates that the deterministic selector can amplify backend-specific evidence changes into different retained rows and later profile state. The diagnostics do not isolate a compression-math defect.

## Limitations and next steps

Order search can rescue enrollment failures when different temporal context exposes already available channels. It cannot safely repair the stable collisions observed in Task 08, and a unique global assignment is not evidence. AOSC’s bounded cache loses rows and favors earlier enrollment positions in the measured stream, but the present data do not establish that changing the compression policy is correct. The largest remaining system limit is open-set rejection when every native channel is occupied by an enrolled person. More audio alone does not add channels or guarantee better retained identity evidence.

Task09A therefore ends with **B — Partially Improved**. Backend parity is repeatable on each backend, but independently constructed profiles produce materially different AOSC state and change PV-01/PV-02 decisions; evaluation of the fixed CPU-built PV-03 profile adds a one-frame near-threshold change. No GPU-specific correctness bug was isolated. A Task09B plan would need to preserve enrollment abstention and explicitly solve/measure UNKNOWN rejection; it is outside this task.
